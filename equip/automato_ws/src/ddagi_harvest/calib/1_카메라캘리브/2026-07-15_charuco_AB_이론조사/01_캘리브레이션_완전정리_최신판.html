🤖 로봇팔 캘리브레이션 — 완전 정리

"카메라가 본 토마토"를 "로봇 손끝이 정확히 잡는" 좌표로 바꾸려면 세 개의 변환이 모두 정확해야 합니다. 각 캘리브는 정확히 "어디 ↔ 어디"를 맞추는 작업이에요.

핸드아이 캘리브

Hand-Eye · 카메라↔로봇① 뒤에

2부. ①번(카메라 내부) 결과값을 코드에서 어떻게 쓰나

이 코드는 ①번(카메라 내부)에 대한 것
캘리브는 딱 한 번. 결과(K·왜곡)를 파일에 저장해두고 이후엔 불러다 쓰기만 합니다. (매번 재캘리브 X)

① 캘리브 실행 · 딱 한 번

# calibrate_camera.py — 한 번만 실행
ret, K, dist, _, _ = cv2.calibrateCamera(objpoints, imgpoints, size, None, None)
np.savez("cam_calib.npz", K=K, dist=dist)   # 결과를 파일로 저장

② 불러오기 · 프로그램 켤 때 한 번

# auto_scan_pick.py 시작 부분
d = np.load("cam_calib.npz"); K, dist = d["K"], d["dist"]   # 저장값 꺼냄(재계산 아님)

③ 매 프레임 사용 · 찍을 때마다 (재캘리브 X)

while True:                      # 토마토 찍을 때마다
    X = (u - K[0,2]) / K[0,0] * z   # K로 픽셀→3D "계산"만 (K를 다시 구하는 게 아님)
    ...  cv2.solvePnP(obj, corners, K, dist)

비유 — 캘리브 = 자를 한 번 정밀하게 만드는 일, 매 프레임 = 그 자로 재는 일. 잴 때마다 자를 새로 만들지 않죠. 똑같습니다.

지금 우리 코드는 파일 대신 카메라에서 꺼낼 뿐 패턴은 동일: get_intrinsics()로 시작 시 한 번 로드 → 매 프레임 사용. 내 값으로 바꾸려면 "불러오는 두 줄"만 교체, 나머지(solvePnP·픽셀→3D)는 그대로.

3부. 순서는 2가지 — 서로 완전히 무관

캘리브를 어떤 순서로 하든, 실제 집기 순서에는 아무 영향이 없습니다.

① 캘리브 순서 (준비)② 실제 집기 순서 (사용)
언제딱 한 번 (설정할 때)매번 (토마토 잡을 때마다)
무엇값 3개를 만드는 순서저장된 값 3개를 쓰는 순서
바뀌나2·3은 자유 (아무렇게나)항상 고정 (안 바뀜)

실제 집기 순서 (항상 이대로, 코드가 자동으로):

카메라가 봄→13D 점→3로봇 좌표→2도구 끝 명령

왜 고정이냐? ①로 픽셀→3D를 먼저 해야 ③이 로봇 좌표로 바꾸고, 그래야 ②로 도구 끝을 보낼 수 있어요. 앞 결과가 있어야 뒤가 되는 데이터 흐름이라 순서를 못 바꿉니다 — 캘리브를 어떻게 했든 무관하게.

✅ 직접 답: TCP(②)를 ③보다 먼저 하든 뒤에 하든 → 실제 집기 순서엔 0의 영향. 집기는 항상 1→3→2 로 코드가 자동으로 합니다. 캘리브는 "값 3개 만들어 저장"일 뿐, 다 만들면 만든 순서는 잊어도 됩니다.

4부. A와 B는 다른 것 — "K를 만들기 vs 쓰기"

가장 헷갈리는 지점. ①(내부, A) 은 K를 만드는 일, ③(핸드아이, B) 는 그 K를 가져다 쓰는 일. B를 했다고 A를 한 게 아니다.

K(카메라 내부값)를 얻는 방법은 2가지 — 이 둘은 완전히 다르다:

# 경로 ① get_intrinsics() — 그냥 "읽기" (계산 아님)
intr = profile.get_stream(...).get_intrinsics()   # D435 펌웨어에 박힌 공장값을 읽어옴
# → 내 사진 한 장도 계산 안 함. 뭘 찍든 항상 같은 값.

# 경로 ② cv2.calibrateCamera() — "계산" = 이게 진짜 A
ret, K, dist, _, _ = cv2.calibrateCamera(objpoints, imgpoints, size, None, None)
# → 내 판 사진들로 내 카메라 전용 K를 산출. 매번 다름.
get_intrinsics()calibrateCamera() = A
하는 일공장값 읽기내 사진으로 계산
내 사진 쓰나안 씀씀
매번 같은 값?항상 같음매번 다름
A를 한 건가?❌ 아니오✅ 예

B(핸드아이)가 K를 쓰는 지점은 딱 한 곳 — solvePnP:

cv2.solvePnP(obj, corners, K, dist) → R,t   # 판 자세. 여기서 K를 "입력"으로 소비
cv2.calibrateHandEye(Rg,tg, Rb,tb) → X       # 여긴 K가 아예 안 들어감

즉 B는 K를 소비만 하고 만들지 않는다. K를 공장에서 빌리면 A를 건너뛰고도 B가 된다.

✅ 7/3에 실제로 일어난 일: get_intrinsics()로 공장 K를 읽어서 solvePnP에 넣고 B 완료. cv2.calibrateCamera는 호출조차 안 됨 → 그래서 A는 "안 한" 것. ("B 했으면 A도 한 것 아니냐" → 아니오)

5부. 차루코(ChArUco) = 흰검판 + 아르코마커

✦

차루코란?

ChArUco = Chessboard + ArUco
정확히흰검 체커판의 "흰 칸"마다 아르코마커(고유 ID 흑백코드)를 하나씩 박은 판
일반 체커판 — 판이 화면에서 조금이라도 잘리면 "몇 번째 코너인지" 구분 불가 → 그 사진 통째 버림. (7/3에 J4 ±20° 자세에서 검출 실패한 이유)
차루코 — 흰 칸마다 고유 번호가 있어 판이 절반 잘려도 인식 → 화면 구석·가장자리까지 밀 수 있음.
왜 중요? 렌즈 왜곡은 화면 가장자리에서 결정됨 → 판을 구석까지 밀어야 A(내부캘리브)가 잘 됨. 차루코라야 그게 가능. 강사님 "차루코" 권장의 진짜 이유.

6부. 차루코 1장으로 A+B를 "한 번에" — 촬영은 1번, 계산은 따로

"따로 해야 한다"(계산 2개) 와 "한 번에 된다"(촬영 1번) 는 다른 층위라 모순이 아님.

층위따로인가 / 한 번인가
계산 함수따로. calibrateCamera(A) 와 calibrateHandEye(B)는 별개 함수 — 게다가 A 먼저 → B 나중 순서까지 있음
결과물따로. A는 K, B는 X (다른 값)
판·촬영(물리작업)한 번. 차루코 1장 고정 + 로봇 자세순회 1회로 찍은 사진을 두 계산이 공유

데이터 흐름 (카메라가 팔에 달려 eye-in-hand라 판이 저절로 다양한 각도로 찍힘):

차루코 고정 + 로봇 30자세 순회
= 사진 한 세트→calibrateCamera
→ K  (A)→solvePnP(K)
→ 판자세→calibrateHandEye
→ X  (B)

촬영은 하나로 합쳤지만, 계산 A·B는 여전히 별개로 순서대로 돕니다. 이 스크립트는 7/3과 달리 calibrateCamera를 실제로 실행 → 처음으로 A를 "함" + B도 새 K로 다시 잡음.

판 생성 → A4 100% 인쇄 → 딱딱한 판에 평평하게 → 자로 실측

python3 calibrate_cam_handeye_charuco.py --make-board board_charuco.png

7부. 우리가 실제로 한 것 + 팀원 오해 정정

#캘리브맞추는 것우리 상태
①카메라 내부 (A)픽셀 ↔ 3D 광선직접 안 함 — 공장값 읽어 씀 → ✅ 이제 스크립트 생김
②TCP플랜지 ↔ 도구 끝goff 손보정으로 반영
③카메라↔base (B)카메라 ↔ 로봇 좌표7/3 직접 완료 2.6mm(체커판) → 차루코 개선 예정

❓ 팀원: "③은 공장에서 적용돼 나왔다" — 맞나?

D435 셋업 기준 틀림. Elephant Robotics 공식 문서도 "카메라 (재)장착 시 hand-eye는 사용자가 직접" 이라 명시. 게다가 너희는 기본 2D 카메라를 떼고 D435를 자가 장착 → 공장 매트릭스가 있어도 2D 전용이라 무효. handeye.json도 "개체 전용"(= 공장 공통 상수 아님).

진짜 공장 적용된 것 = 로봇의 관절 영점·순기구학(base→플랜지) — "로봇이 자기 손끝 위치를 아는 것". 팀원이 떠올린 게 이것. 카메라↔base(③)와는 다른 것이다.

🎯 한 줄 결론 — 캘리브는 ①내부(A)·②TCP·③카메라↔base(B) 3종. 우린 ③(B)만 공장 K 빌려서 했고(①A는 읽기만, 직접계산 X), ③은 공장 게 아니라 우리가 한 것. 이제 차루코 1장으로 A를 진짜 계산 + B까지 한 번에 다시 잡으면 끝. → calibrate_cam_handeye_charuco.py
