🤖 로봇팔 캘리브레이션 — 완전 정리

"카메라가 본 토마토"를 "로봇 손끝이 정확히 잡는" 좌표로 바꾸려면 세 개의 변환이 모두 정확해야 합니다. 각 캘리브는 정확히 "어디 ↔ 어디"를 맞추는 작업이에요.

1부. 세 가지 캘리브레이션 — 정확히 무엇을 맞추나

1

카메라 내부 캘리브

Camera Intrinsic가장 먼저 · 필수
정확히이미지 픽셀(2D) ↔ 카메라 3D 방향 — 렌즈가 픽셀과 실제 3D 광선을 잇는 카메라 내부 관계를 맞춤
구하는 값fx,fy(초점거리) · cx,cy(이미지 중심) · 왜곡계수
방법체커보드 20~30장 촬영 → cv2.calibrateCamera → K·distCoeffs 산출
왜 맨 먼저? 픽셀→3D 역투영의 출발점이라, 틀리면 ③·②까지 오차가 그대로 누적됩니다.
현재 — 직접 안 하고 D435 공장값 사용. 값은 카메라 안에 있고 get_intrinsics()가 실행마다 받아옴(파일 저장 X).
2

TCP 캘리브

Tool Center Point · 공구 중심점순서 자유
정확히플랜지(팔 끝 장착면) ↔ 도구 끝(TCP) — 이 둘 사이의 위치 오프셋을 맞춤
구하는 값플랜지 → 도구 끝 오프셋 (x,y,z·방향)
방법도구 끝을 고정된 한 점에 다른 자세로 4번↑ 대기 → "항상 같은 점" 제약으로 오프셋 역산 (수동)
플랜지 = 팔 맨 끝 공구 장착 면. 로봇은 여기까지만 정확히 앎 → 그 앞 도구 끝은 ②로 알려줘야 함. (강사님 "플랜지" 이야기)
현재 — 집기 코드에 goff(손목↔손끝 보정) 오프셋으로 반영.
3

핸드아이 캘리브

Hand-Eye · 카메라↔로봇① 뒤에
정확히카메라 ↔ 로봇 베이스(좌표계) — 카메라가 본 좌표를 로봇 좌표로 바꾸는 변환 X를 맞춤
구하는 값카메라 → 로봇 변환 X (eye-in-hand: 카메라↔플랜지)
방법체커판 고정 → 여러 자세로 (로봇 자세, 카메라가 본 체커판) 짝 수집 → cv2.calibrateHandEye(A·X=X·B)
자가검증 체커판은 고정 → 모든 자세에서 계산한 board 위치의 퍼짐(mm)이 작을수록 잘 된 것 = 품질 지표.
현재 — calibrate_handeye_full.py 있음(18자세 자동 수집).

2부. ①번(카메라 내부) 결과값을 코드에서 어떻게 쓰나

이 코드는 ①번(카메라 내부)에 대한 것
캘리브는 딱 한 번. 결과(K·왜곡)를 파일에 저장해두고 이후엔 불러다 쓰기만 합니다. (매번 재캘리브 X)

① 캘리브 실행 · 딱 한 번

# calibrate_camera.py — 한 번만 실행
ret, K, dist, _, _ = cv2.calibrateCamera(objpoints, imgpoints, size, None, None)
np.savez("cam_calib.npz", K=K, dist=dist)   # 결과를 파일로 저장

② 불러오기 · 프로그램 켤 때 한 번

# auto_scan_pick.py 시작 부분
d = np.load("cam_calib.npz"); K, dist = d["K"], d["dist"]   # 저장값 꺼냄(재계산 아님)

③ 매 프레임 사용 · 찍을 때마다 (재캘리브 X)

while True:                      # 토마토 찍을 때마다
    X = (u - K[0,2]) / K[0,0] * z   # K로 픽셀→3D "계산"만 (K를 다시 구하는 게 아님)
    ...  cv2.solvePnP(obj, corners, K, dist)

비유 — 캘리브 = 자를 한 번 정밀하게 만드는 일, 매 프레임 = 그 자로 재는 일. 잴 때마다 자를 새로 만들지 않죠. 똑같습니다.

지금 우리 코드는 파일 대신 카메라에서 꺼낼 뿐 패턴은 동일: get_intrinsics()로 시작 시 한 번 로드 → 매 프레임 사용. 내 값으로 바꾸려면 "불러오는 두 줄"만 교체, 나머지(solvePnP·픽셀→3D)는 그대로.

3부. 순서는 2가지 — 서로 완전히 무관

캘리브를 어떤 순서로 하든, 실제 집기 순서에는 아무 영향이 없습니다.

① 캘리브 순서 (준비)② 실제 집기 순서 (사용)
언제딱 한 번 (설정할 때)매번 (토마토 잡을 때마다)
무엇값 3개를 만드는 순서저장된 값 3개를 쓰는 순서
바뀌나2·3은 자유 (아무렇게나)항상 고정 (안 바뀜)

실제 집기 순서 (항상 이대로, 코드가 자동으로):

카메라가 봄→13D 점→3로봇 좌표→2도구 끝 명령

왜 고정이냐? ①로 픽셀→3D를 먼저 해야 ③이 로봇 좌표로 바꾸고, 그래야 ②로 도구 끝을 보낼 수 있어요. 앞 결과가 있어야 뒤가 되는 데이터 흐름이라 순서를 못 바꿉니다 — 캘리브를 어떻게 했든 무관하게.

✅ 직접 답: TCP(②)를 ③보다 먼저 하든 뒤에 하든 → 실제 집기 순서엔 0의 영향. 집기는 항상 1→3→2 로 코드가 자동으로 합니다. 캘리브는 "값 3개 만들어 저장"일 뿐, 다 만들면 만든 순서는 잊어도 됩니다.

🎓 강사님이 "①도 직접 하라"면 — 지금은 공장값 사용 중이라 체커보드로 내 카메라 전용 값을 산출·파일 저장하는 코드는 없습니다. 만들면 위 2부의 "파일 저장→불러오기"로 바로 연결되고, RP-91(재캘리브)과 딱 맞습니다.
