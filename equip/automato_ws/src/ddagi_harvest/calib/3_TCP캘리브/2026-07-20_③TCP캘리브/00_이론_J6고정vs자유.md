# TCP 손터치 — 왜 그때(2026-07-11)는 J6 고정, 지금은 자유인가

## 0. 한 줄 요약
J6 고정 여부는 **손목을 잠그느냐의 문제가 아니라, 플랜지의 "방향(회전)"을
가정하느냐 vs 측정하느냐의 문제**다.
- 그때: 방향을 **일정하다고 가정** → 그 가정을 지키려 손목(J6) 고정 (그래도 부족)
- 지금: 방향을 **순기구학 TF로 매번 측정** → 가정 불필요 → J6 포함 전부 자유

---

## 1. TCP란 무엇인가 (핵심 수식)
로봇은 **플랜지**(팔목 끝 금속판)의 위치·방향을 정확히 안다.
우리가 원하는 건 **그리퍼 집는 점**인데, 이건 플랜지에서 일정하게 떨어진 곳이다.

이 "일정한 오프셋 벡터"가 **TCP**이고, **툴(플랜지) 좌표계에서는 절대 안 변한다**
(그리퍼가 볼트로 고정돼 있으니까). 예: `TCP_tool = [0, 0, 80] mm` (툴 z축으로 80mm 앞).

base 좌표계에서의 관계식:
```
집는점_base = 플랜지위치_base + R_flange · TCP_tool
```
- `R_flange` = base 기준 플랜지의 **방향(회전행렬)**
- `TCP_tool` = 툴 좌표계의 고정 오프셋 (우리가 구하려는 값)

핵심: 같은 `TCP_tool`이라도 **플랜지가 어느 방향을 보느냐(R_flange)에 따라
base에서의 집는점 위치가 달라진다.** (막대기를 손에 쥐고 손목을 돌리면
막대 끝이 공간에서 다른 곳을 가리키는 것과 같다.)

---

## 2. 손터치로 TCP를 푸는 법 — 필요한 3가지
위 식을 `TCP_tool`에 대해 풀면:
```
TCP_tool = R_flange⁻¹ · (집는점_base − 플랜지위치_base)
```
손끝을 토마토에 댄 순간 필요한 3가지:
1. **집는점_base** = 토마토 좌표 → 카메라(핸드아이)로 측정 ✅
2. **플랜지위치_base** = 순기구학 위치
3. **R_flange (플랜지 방향)** = 순기구학 방향  ← **여기가 그때/지금을 가른다**

---

## 3. 그때(2026-07-11): 방향을 "가정"해서 고정이 필요했다
그때는 **핸드아이가 아직 없어서**, 핸드아이와 TCP를 **동시에** 추정하려 했다.
적은 데이터로 풀려고 **단순화 가정**을 씀:
> "매 터치마다 플랜지 방향 `R_flange`를 (거의) **일정하게** 유지하자."

`R_flange`가 일정하면 식에서 상수로 빠져 계산이 쉬워진다.
그 일정함을 물리적으로 지키려고 **손목(J4~J6)을 잠근** 것 = **J6 고정의 진짜 이유**.

---

## 4. 그 가정이 깨진 이유 (J1이 방향을 바꾼다)
`R_flange`는 **base 기준** 방향이다. 손목을 잠가도, 손으로 팔을 옮기면
**베이스축 J1이 돌아가고**, J1이 돌면 base 기준 손끝 방향이 같이 돈다.

실제 그때 기록:
| 쌍 | 손목 yaw(rz) |
|---|---|
| 1 | −86° |
| 2 | −59° |

**손목을 잠갔는데도 rz가 27° 바뀜.** → "방향 일정" 가정이 깨짐 → 고정만으론 부족.

---

## 5. 지금: 방향을 "측정"하니 고정이 불필요
지금은 두 가지가 다르다:
1. **핸드아이 완료·검증(3.4mm)** → TCP만 구하면 됨 (동시추정 불필요)
2. **플랜지 방향 `R_flange`를 순기구학 TF(robot_state_publisher)로 매번 통째로 읽음**
   → 일정하다고 **가정할 필요 없이 실제값을 그대로** 식에 넣음

`R_flange`를 매번 정확히 넣으니, 플랜지가 어떤 방향이든 식이 성립한다.
→ **J6(손목)뿐 아니라 J1~J6 전부 자유.** 그때 "부족"의 원인이던 방향 변화를,
지금은 오히려 **정확히 반영**한다. (방향 다양성이 많을수록 검증이 더 튼튼해짐)

---

## 6. 숫자 예시 (진짜 TCP_tool = [0,0,80]mm 라고 가정)
**터치 #1** — 플랜지가 아래를 봄(R1), 플랜지 base=[200,0,300], 토마토 base=[200,0,220]
```
TCP = R1⁻¹·([200,0,220]−[200,0,300]) = R1⁻¹·[0,0,−80] = [0,0,80] ✅
```
**터치 #2** — 같은 토마토, 손목 비틈(R2), 플랜지 base=[180,20,310]
```
올바르게: TCP = R2⁻¹·([200,0,220]−[180,20,310]) = R2⁻¹·[20,−20,−90] = [0,0,80] ✅
(지금 방식: R2를 측정해서 넣음)

잘못하면: R2를 안 재고 R1로 계산 → R1⁻¹·[20,−20,−90] ≠ [0,0,80] ❌
(그때 방식: 방향 일정 가정 → 27° 오차가 이렇게 새어나옴)
```
→ **방향을 매번 측정하면 어떤 자세든 같은 TCP가 나온다.** 이게 J6 자유의 근거.

---

## 7. 정리 표
| | 그때(2026-07-11) | 지금(2026-07-20) |
|---|---|---|
| 핸드아이 | 없음(TCP와 동시추정) | 완료·검증(3.4mm) |
| 플랜지 방향 R_flange | **일정 가정** → 손목 고정 | **TF로 매번 측정** |
| J1 회전 영향 | 가정 깨짐(rz 27° 변화) | 측정에 완전 반영 |
| J6 | **고정 필요** | **자유** |
| 정확도 한계 | 가정 오차 누적 | 자세 다양할수록 향상 |

**결론:** 방법(힘풀고 손터치)은 같지만, "방향을 가정 → 측정"으로 바뀌면서
J6 제약이 사라졌다. 지금이 그때보다 **원리적으로 더 정확한 상위 버전**이다.
